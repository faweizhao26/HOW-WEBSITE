# Unified Ticket Settings Implementation Plan

**Goal:** 在票种页面一次完成个人票或团体票设置，团票订单页面只管理核款、订单与领取。

**Architecture:** 延用现有票种、团体配置和订单表。新增管理员原子保存 RPC，同时保存票种及团体配置；稳定的客户端票种 ID 让未确认保存可重试。既有团票不能改回个人票；个人票转团票时拒绝已有报名或渠道关联。已有订单金额和期限快照不变。

**Tech Stack:** Next.js 16.3.8, React 19, Supabase/Postgres, Zod, ego-lite.

## Design

- 采用上轮用户认可的单页设置方案；仅增加跨页说明不能消除分步保存和冲突开关，因此不采用。
- 票种弹窗选择个人/团体；团体显示每人单价、人数范围、领取截止、新订单开放开关，不显示免费票及渠道码开关。金额 0 表示免费。
- 列表展示类型、团票单价、人数及开放状态；已有团票可直接编辑。票种启用管理整张票，新订单开关只管理下单。
- 团票订单移除独立配置表单，保留跳转票种入口。渠道码新增仅能选择个人票，历史团票关联仍可辨认但不可继续保存。
- 只在隔离数据库/本机验收，不自动修改生产数据，不推送或部署。
