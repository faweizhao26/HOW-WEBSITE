## 网站内授权

现有管理员登录后，点击前台「管理后台」，进入「账号管理」：

1. 对方先注册网站账号。
2. 按邮箱或姓名搜索，也可选择角色后搜索；列表按每页 20 条分页。
3. 点击「授予管理员」或「撤销管理员」，核对账号后确认。
4. 对方刷新或重新登录；获得权限后可见前台入口，撤销后后台请求被拦截。

被授予的管理员具有同等的内容管理和账号授权权限；当前没有另设超级管理员角色。
不能在网站里撤销自己的管理员权限，数据库也会阻止撤销最后一名管理员。
网站显示最近 20 条权限变更，完整记录保存在 `public.account_role_changes`。
记录由数据库事务与角色更新一起写入，普通账号不能读取，也不能伪造或修改。
已有管理员无需重新注册或重新授权。

授权以 `public.profiles.role` 为准，不依赖 Auth metadata。
页面仅调用经过服务端身份验证的操作；数据库函数再次检查管理员身份，
角色列仍禁止通过普通资料修改接口更新。并发请求串行处理，等待期间被撤权的调用者不能继续授权。
若列表中的角色已被别人修改，提交返回冲突，需要刷新再操作。

数据库迁移文件：`supabase/migrations/20261015061725_admin_account_management.sql`。
发布时需先执行此迁移，再部署应用；不需要重新分配现有管理员权限，也不需要服务端 service-role 密钥。
2026-10-15 用户确认推送后，迁移已应用到正式环境，文件版本与实际迁移记录对齐。

## 数据库人工方式（备用）

网站账号的管理角色保存在 `public.profiles.role`，取值为 `user` 或 `admin`。
正式版本已支持网站内授权，但登录账号（包括网站管理员）仍没有直接修改该列的数据库权限，
必须走受控的授权函数。数据库管理员仍可在控制台使用以下备用操作。
网站管理员身份与 Supabase 项目的控制台权限是两回事。

有数据库编辑权限的 Supabase 项目管理者可按以下步骤授权：

1. 对方先注册网站账号。
2. 在 Supabase 的 Authentication → Users 中按邮箱找到对方，复制 User UID。
3. 在 Table Editor → `public.profiles` 中，按相同的 `id` 找到资料行。
4. 将这一行的 `role` 从 `user` 改为 `admin` 并保存；撤销时改回 `user`。
5. 对方刷新网页，或重新登录。

不需要修改 Authentication 用户的 JWT `role`，也不靠 `user_metadata.role` 授权。

## 后续迁移平台

用户界面及操作契约依赖网站业务角色，不直接调用 Supabase 控制台或管理用户 API。
Supabase RPC 适配集中在 `src/lib/admin/accounts.ts`，角色和历史记录可随业务数据导出。
未来更换平台仍需适配登录验证、数据库调用及账号邮箱查询；迁移记录中的 `auth.users` 关联
需要改为新平台的身份来源，不能只替换连接地址。
