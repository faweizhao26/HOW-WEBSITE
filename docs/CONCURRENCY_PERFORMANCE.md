# 公开内容缓存与并发验收

日期：2026-10-20。分支：`codex/public-content-load-testing`，基线：`6020984`。
状态：优化代码本地完成，未提交、推送或部署，无正式请求压测或正式业务写入。
容量结论：本机 100 连接短时测试通过；300 档复测不稳定，500 档未通过，不能换算成正式网站同时在线人数。

## 代码变化

- 公开配置、讲者、演讲、赞助商、动态和议程使用独立匿名 Supabase 客户端；不读取 cookies，
  不保存会话，清除 Cookie 头并固定匿名授权。只允许六类已发布数据的 GET；两个发布表必须只读当前 payload。
- 使用 Next.js fetch Data Cache，60 秒再验证周期、统一 `how:published-content` 标签。
  相同匿名 GET 在一次服务端渲染内去重，成功内容跨请求复用；不自行添加全局用户数据缓存。
  Next 当前实现仅缓存 HTTP 200，冷缓存数据库错误仍显示原有错误，不伪装成空内容或演示数据。
- 12 个发布、撤销发布及回滚动作在 RPC 成功后执行 `updateTag`，再刷新受影响页面。
  权限拒绝或 RPC 失败不清缓存；草稿保存不影响公开缓存。
- 账号、权限、报名、票种及渠道码校验、签到和胸牌打印配置仍实时读取/写入。
  未缓存整页 HTML、登录态或私人 API；语言和主题 Cookie 保持原行为。
- 站外直接修改数据库或调用发布 RPC 不会触发站内标签失效，要等待再验证。
  60 秒是再验证周期而非严格最大陈旧时间；后台刷新失败时，框架可能继续提供最后成功的缓存。

## 压测方式

新增 `npm run test:load`，使用 Autocannon 8.0.0，pipelining=1，不设置请求速率。
默认档位 50、100、300、500 连接，浏览每档每端点 10 秒，写入为每档一次等量突发。
这是 HTTP/1.1 闭环测试，没有完整浏览器资源下载、用户思考时间或登录/邮件流程。
固定数量写入的 requests/s 受工具采样区间影响，不能当作持续写入吞吐上限。

执行要求：

- 显式设置 `PUBLICATION_TEST_ISOLATED_PROJECT=true`；只接受带端口的 loopback HTTP origin，拒绝公网、账号密码、路径及查询参数。
- 私有夹具必须为专用 `how_audit_reliability_20261018` 库，应用地址必须与夹具配对。
  当前服务由隔离构建脚本启动；不要拿使用正式数据库的本机服务作为目标。
- 专用库已启用 `pg_stat_statements` 统计扩展，未给正式库增加扩展或迁移。
- 输出只包含指标、资源和结果计数，不序列化原始配置、授权头或夹具凭据。
- 写入账号使用仅限本机的签名 JWT，经过真实 PostgREST 验签、RLS、触发器、唯一约束和条件更新；
  不包含真实注册、收信、密码登录或现场打印。
- 任一档错误即停止升压，finally 清理本批账号、报名和票种，并核对原始行数。
  若进程被强制终止，需清理对应 `load-<run UUID>-...@example.test` 夹具后再测。

复测本机已通过的范围（夹具不进入 Git）：

```sh
PUBLICATION_TEST_ISOLATED_PROJECT=true \
HOW_LOAD_FIXTURE=/private/tmp/how-audit-reliability-20261018/fixture.json \
HOW_LOAD_LEVELS=50,100 \
HOW_LOAD_REPORT=/private/tmp/how-load-report.json \
npm run test:load
```

`HOW_LOAD_MODE=browse` 只测页面和公开 API，`writes` 只测报名/签到接口，默认 all。
`HOW_LOAD_DURATION` 允许 2–30 秒；`HOW_LOAD_WORKERS=1–4` 仅影响浏览压测器，连接数需整除工作线程数。
多线程模式没有逐请求 p95 事件，报告 p95 为 null，保留工具 p97.5，不把它冒充 p95。

## 环境与结果

Apple M5、10 个逻辑 CPU、24 GB 主机内存；应用、压测器和 Docker 数据库共用一台机器。
Next.js 16.3.8 生产构建，本机 PostgreSQL 17，`max_connections=100`。
未验证 Vercel/Supabase 正式套餐资源、扩容、配额、跨区域网络或大陆用户访问表现。

单工作线程、100 连接、每端点 10 秒对比：

| 场景 | 优化前 HTTP p95 | 优化后 HTTP p95 | 优化前完成请求 | 优化后完成请求 | 热缓存公开数据查询 |
| --- | --- | --- | --- | --- | --- |
| 首页 | 372.55 ms | 332.08 ms | 3,263 | 4,043 | 6,726 → 0 |
| 公开内容 API | 75.31 ms | 42.97 ms | 15,506 | 29,745 | 15,606 → 0 |

两组 50/100 档均无连接错误、超时、非 2xx 或内容校验失败。查询计数来自专用库已发布表查询的
pg_stat_statements calls 差值，结束时可能包含尚未完成响应的查询，不是精确逐请求计费。
“0”仅指本轮热缓存窗口的公开查询，不包括认证、私人资料或业务写入。

| 范围 | 观察结果 | 判定 |
| --- | --- | --- |
| 300 连接浏览 | 单线程和四工作线程均出现大量 ECONNRESET；另一个 2 秒首页诊断曾成功，但 API 失败 | 未通过 |
| 500 连接浏览 | 300 档失败后停止，没有继续执行 | 未验收 |
| 50/100 条报名及签到突发 | 两轮均全部成功并核对数据库行数 | 本机短时通过，不含登录流程 |
| 300 条报名及签到突发 | 第一轮 300/300 均成功；补测报名完成 268，32 次 ECONNRESET | 不稳定，不算通过 |
| 500 条报名突发 | 完成 325，175 次 ECONNRESET；随后停止，未执行该档签到 | 未通过 |
| 同账号 20 次报名 | 1 次 201，19 次 409/23505，数据库只有一条 | 一致性通过 |
| 同记录 20 次签到 | 1 次更新成功，19 次因原状态不匹配返回 406，数据库只签到一次 | 一致性通过 |

连接重置并不等于压测通过。对照的临时纯 Node HTTP 服务在 300 连接下也出现 14,798 次 ECONNRESET，
移除 Next.js 和数据库仍可复现；已排除“只能由网站业务代码引起”的判断，但尚未完全区分本机网络与工具的具体原因。
本机监听队列上限读数为 128，未修改系统参数，不能单凭读数证明唯一根因。
四工作线程复测未解决问题，没有继续反复调参制造成功结果。

可报告的是“100 连接本机短测通过、缓存明显减少数据库读取”，不能报告“正式网站支持 300/500/1000 人”。
高档位应在独立压测机及与正式规格相近的隔离部署上验证；持续负载、冷启动、混合浏览/写入、
真实登录和流量突增仍是验收缺口。
