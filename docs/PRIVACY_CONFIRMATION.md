# 隐私确认

更新：2026-11-25。隐私确认随 [Docker 部署](DOCKER_DEPLOYMENT.md) 交付，
不在本批切换正式站。以下保留初次本地验收范围。

## 使用变化

- 普通浏览不弹出强制同意框，不新增首次访问记录或追踪 Cookie。
- 创建账号、个人报名和团票领取均增加默认不勾选的隐私条款确认。
- 未确认不能提交；网站服务端也拒绝缺失、false 或伪造类型的确认值。
- 条款链接在新标签页打开，原表单内容保留。已有账号及已有报名不补填确认。
- 个人报名切换账号或重新加载时重置确认；团票表单随账号重新挂载。
- 隐私正文继续使用 `/privacy` 的后台已发布内容，本批不替换正文。

## 实现边界

共用原生 required checkbox，保留键盘操作和中英文、日夜主题样式。
浏览器仍使用原有 Supabase SDK 的注册、PKCE、会话和广播流程；仅 signup 请求
改由同站 `/api/auth/signup` 校验后转发。登录、刷新会话和数据库请求不改路径。
代理保留 PKCE challenge、确认回调、认证错误码及 Retry-After，不在服务端另建会话。

注册 metadata 和个人报名 custom_fields 保存 `privacy_consent`，包含 accepted、
服务端 accepted_at 和 policy_path。团票领取通过服务端 action 校验，再调用原有
原子 RPC，不另存同意审计记录，不改变名额重试语义。

这是网站提交入口的确认，不改变 Supabase 原始公开 signup/RPC 权限，不是不可篡改的审计。
代理只使用现有公开 anon key，没有新增管理密钥、依赖、数据库迁移或 Auth 配置。
注册转发会共用网站服务端出口；本批未测量上游按 IP 限流容量。

## 本地验收

- 完整测试 243/243 通过；随后针对 Auth 错误版本标记补充回归，最终 8/8 隐私测试通过。
- 最终零警告 lint、46 路由生产构建通过。
- 真实 Supabase JS SDK 配合模拟 Auth，验证 PKCE 生成、错误码及确认后 verifier 交换。
- ego-lite 实测未确认拦截、链接新标签及表单保留、账号注册、个人报名和团票领取成功。
- 1512px/390px、中英文、日夜主题共 24 种表单显示组合，无横向溢出；桌面及手机截图已查看。
- 首页没有新增确认弹窗或 checkbox。最终浏览器请求确认未同意时返回 privacy_required 400。

Docker 未启动，本轮后端为回环地址的模拟 Auth/REST，不是实际隔离 PostgreSQL，
未发送邮件、操作正式账号或写正式业务记录。实际 SDK、Next 路由及 server action 参与验收。
本机 PKCE 回调曾因既有 Next 开发服务器内部 origin 从 127.0.0.1 跳向 localhost；
verifier 交换成功后回到原地址可读取会话。后续 Docker 批次已修正回调的公开地址，
并验证反代跳转；上述本地验收不算正式邮件闭环验收。
